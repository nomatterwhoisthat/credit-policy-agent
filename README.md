# Ассистент по кредитным решениям: поиск по документам и агент на LangGraph

## Задача

Сотруднику банка приходит клиент с заявкой. Ему нужно быстро узнать три вещи. Какое решение рекомендует модель. Почему именно такое. Что на этот счёт говорит внутренняя политика. В проекте собран ассистент, который отвечает на такие вопросы. Он сам вызывает нужные инструменты: считает вероятность дефолта клиента и ищет ответ в документах.

Отдельно проверено, насколько хорошо работает поиск по документам. Для этого на открытом бенчмарке сравнены четыре способа поиска.

## Зачем это сделано

Показать две вещи, которые нужны в работе с языковыми моделями. Первая это измерение. Выбор способа поиска подтверждён цифрами с доверительными интервалами, а не вкусом. Вторая это защита от выдуманных чисел. В кредитных решениях ошибка в одной цифре ведёт к неверному решению, поэтому ответ агента проверяется программно.

Проект продолжает `credit-decision-engine`. Из него взяты модель PD и калибровщик (папка `artifacts/`).

## Откуда данные

Бенчмарк поиска. FiQA-2018, вопросы и ответы из финансовых форумов. Загружается с Hugging Face (`mteb/fiqa`, это BEIR/FiQA). В полном виде 57 638 документов. Для проверки использовано 648 тестовых вопросов с известными релевантными документами.

База знаний агента. Семь коротких документов в папке `kb/` (карточка модели, правило решения, словарь терминов, политика мониторинга, политика проверки на дискриминацию, правила объяснения отказа, описание признаков). Они написаны специально для этого проекта и опираются на результаты `credit-decision-engine`. Это не настоящие документы банка.

Клиенты для демонстрации. Три реальные записи из тестовой части набора Default of Credit Card Clients (`examples/sample_clients.json`). Они названы `low_risk`, `high_risk` и `borderline`.

## Что сделано

**1. Сравнение способов поиска (`experiments/run_retrieval_benchmark.py`).**
Проверено пять вариантов. BM25 (поиск по словам). Dense, то есть эмбеддинги модели `BAAI/bge-small-en-v1.5`. Гибрид BM25 и dense через RRF (объединение двух рейтингов по местам). Гибрид с переранжированием топ-30 кросс-энкодером `ms-marco-MiniLM-L-6-v2`. Dense-модель, дообученная на 3 000 парах «вопрос и ответ» из обучающей части FiQA (1 эпоха, in-batch negatives). Для каждого варианта посчитаны nDCG@10, Recall@10, Recall@100, MRR@10, доверительные интервалы (bootstrap по вопросам) и парный bootstrap-тест против BM25.

**2. Агент (`src/agent/`).**
Граф на LangGraph с тремя узлами. Модель решает, какой инструмент вызвать. Инструменты выполняются. Затем проверяется ответ. Инструментов два. `score_applicant` считает калиброванную PD, решение, порог PD, ожидаемую прибыль и три главные причины по SHAP. `search_knowledge` ищет по папке `kb/` (BM25 плюс dense, объединение через RRF).

**3. Проверка чисел в ответе (`src/agent/groundedness.py`).**
Каждое число в итоговом ответе должно встречаться в результатах инструментов. Допускается округление и запись в процентах. Если найдено число без источника, агент один раз получает замечание и переписывает ответ. Если число осталось, ответ помечается как неподтверждённый.

**4. Подключение модели.**
`OpenAICompatibleLLM` работает с любым сервисом, который поддерживает формат OpenAI chat completions с вызовом функций. Подходят OpenAI, aimlapi.com, vLLM, Ollama. `ScriptedLLM` это простая заглушка с правилами. Она нужна, чтобы тестировать граф без ключа и интернета.

## Результаты

### Поиск на FiQA

Оценка на урезанном корпусе. В него вошли все релевантные документы тестовых вопросов и 8 500 случайных других, итого 10 206 документов. Корпус урезан, потому что кодирование 57 тысяч документов на двух ядрах процессора заняло бы несколько часов. Из-за этого цифры выше, чем в полном FiQA, и сравнивать их с таблицами MTEB нельзя. Между собой варианты сравнивать можно.

| Способ | nDCG@10 (95 % интервал) | Recall@100 | MRR@10 |
|---|---|---|---|
| BM25 | 0,341 (0,314–0,368) | 0,627 | 0,421 |
| Dense bge-small | **0,536** (0,509–0,564) | 0,839 | 0,621 |
| Гибрид BM25 + dense | 0,469 (0,442–0,497) | 0,825 | 0,562 |
| Гибрид + кросс-энкодер | 0,510 (0,483–0,538) | 0,825 | 0,595 |
| Dense после дообучения | **0,537** (0,509–0,563) | 0,845 | 0,621 |
| Гибрид BM25 + дообученный dense | 0,469 (0,441–0,497) | 0,834 | 0,562 |

Что из этого следует.

- Dense-поиск лучше BM25 на 0,195 nDCG@10. Интервал разницы от 0,169 до 0,222, p меньше 0,001 по парному bootstrap.
- Добавление BM25 к dense в этом наборе ухудшило результат, с 0,536 до 0,469. Возможное объяснение. Вопросы в FiQA длинные и разговорные, слова в вопросе и в ответе часто не совпадают, и BM25 добавляет в объединение много неподходящих документов. Это предположение, оно не проверялось. Из вариантов объединения пробовался только RRF с равными весами.
- Кросс-энкодер улучшил гибрид с 0,469 до 0,510, но до чистого dense не дотянул. Переранжирование результатов dense-поиска не проверялось.
- Дообучение на 3 000 парах за одну эпоху не дало улучшения. nDCG@10 0,5365 против 0,5364. Причину не проверяли. Возможно, 3 000 пар мало, или базовая модель уже обучалась на похожих данных. Это отрицательный результат, и он оставлен в таблице.

### Агент

Тесты (`pytest tests/`) проходят, 8 штук. Они проверяют, что число без источника ловится, что при этом ответ с округлением и процентами пропускается, что база знаний находит нужный документ, что решение агента совпадает с правилом (`high_risk` отказ, `low_risk` одобрение), что ошибки инструментов возвращаются модели, а не ломают программу, и что агент исправляет выдуманное число за один повтор.

Оценочный набор из 6 вопросов (`eval/agent_cases.json`) пройден на заглушке `ScriptedLLM`. Правильный выбор инструментов 6 из 6. Все ответы подтверждены результатами инструментов. Решение и ключевое содержание совпали во всех проверяемых случаях.

Важно. Этот прогон проверяет каркас, то есть граф, инструменты и проверку чисел. Он ничего не говорит о качестве языковой модели, потому что заглушка работает по заданным правилам. С настоящей моделью агент не запускался, ключа на момент работы не было. Для проверки с реальной моделью достаточно задать переменные окружения и запустить `eval/run_agent_eval.py` (см. ниже).

Пример вопроса для клиента `borderline`. Вероятность дефолта 0,0859, порог 0,0844. Решение отказать, потому что вероятность выше порога, хотя сама по себе низкая. Порог низкий из-за малого использования лимита. Эту ситуацию разбирает `kb/adverse_action.md`.

## Ограничения

- Корпус для бенчмарка урезан (см. выше).
- Дообучение проверено в одном варианте (3 000 пар, 1 эпоха, одна модель). Это не исследование лучших настроек.
- Агент проверен только с заглушкой. Качество с настоящей LLM не измерено.
- Проверка чисел ловит выдуманные числа, но не ловит неверные выводы из верных чисел.
- Документы в `kb/` учебные, не банковские.

## Как запустить

```bash
pip install -r requirements.txt   # torch в версии для CPU, если нет видеокарты

pytest tests/                                          # 8 тестов, быстро
python -m src.agent.cli "Почему клиент borderline получил отказ?"   # агент на заглушке
python eval/run_agent_eval.py                          # оценка агента, пишет results/agent_eval.json

python experiments/run_retrieval_benchmark.py          # около 30 минут на 2 ядрах CPU, пишет results/retrieval_benchmark.json
```

Вопросы для заглушки должны содержать слова `low_risk`, `high_risk` или `borderline`, иначе клиент не выбирается. С настоящей моделью формулировка свободная.

Запуск с настоящей языковой моделью.

```bash
export LLM_API_KEY=...                       # ключ сервиса
export LLM_BASE_URL=https://api.aimlapi.com/v1   # или другой совместимый адрес
export LLM_MODEL=...                         # модель с поддержкой вызова функций
python eval/run_agent_eval.py
```

## Структура

```
src/agent/      граф LangGraph, инструменты, база знаний, проверка чисел, подключение моделей
src/credit/     признаки и скоринг клиента (модель из credit-decision-engine)
src/            метрики поиска и поисковые модули
kb/             документы базы знаний
experiments/    сравнение способов поиска
eval/           оценочный набор для агента
examples/       три демонстрационных клиента
results/        итоговые таблицы
artifacts/      обученная модель PD и калибровщик
```
